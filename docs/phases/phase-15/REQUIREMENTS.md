# Phase 15 Requirements

Priority: M = must, S = should, C = could. Acceptance references point to [ACCEPTANCE.md](ACCEPTANCE.md).

| ID | Requirement | PRD trace | Pri | Acceptance |
|---|---|---|---|---|
| P15-R01 | Tag key normalization rules map raw keys (case, separators, aliases, e.g. `CostCenter`, `cost-center`) to a normalized key. Value mapping rules map raw values to canonical values (exact, case-insensitive, regex with RE2 only, lookup table). | FR-ALC-001, FR-NRM-005, UJ-04 | M | P15-AC01 |
| P15-R02 | Inheritance rules fill a missing normalized tag on a cost row from the enclosing account/project/subscription/resource-group tags (`cloud_scopes.tags`), with a configurable precedence (resource > resource group > subscription/project > account > org). Explicit resource tags are never overwritten. | FR-ALC-002 | M | P15-AC02 |
| P15-R03 | Business mapping rules (`hierarchy_assign`, `dimension_assign`) evaluate a condition AST over FOCUS dimensions, normalized tags and custom dimensions and assign a hierarchy node or custom-dimension value. Rules are ordered by `position`, first match wins per target attribute. | FR-ALC-003, FR-TEN-003 | M | P15-AC03 |
| P15-R04 | Shared-cost distribution (`shared_split`) supports `even`, `fixed_percentage` (must sum to exactly 100), `proportional_cost` (basis cost metric selectable) and `proportional_metric` (custom unit metric or consumed quantity). A zero or missing basis falls back to a declared fallback method or leaves cost unallocated, never divides by zero. | FR-ALC-004, UJ-04 | M | P15-AC04 |
| P15-R05 | Allocation invariant: for each (tenant, billing_period, billing_currency, cost metric), Σ allocated + Σ unallocated = Σ source exactly at scale 12, and per source row Σ shares = source amount exactly. Residuals from rounding to the currency's minor unit use largest-remainder with a deterministic tie-break. An invariant failure aborts the swap (fail-closed). | FR-ALC-005, NFR-ACC-001, NFR-ACC-003, AC-01 | M | P15-AC04, P15-AC05 |
| P15-R06 | Rule sets are versioned and immutable once published. Draft edits require `If-Match`. Publish records publisher, checksum (SHA-256 of canonical JSON) and `effective_from`. Prior versions remain queryable. | FR-ALC-006 | M | P15-AC06 |
| P15-R07 | Preview computes allocation for a draft over a chosen period range without touching live data and returns a diff against the live version: totals per hierarchy node and dimension, rows changing target, unallocated delta, overlap and dead-rule warnings. | FR-ALC-006, UJ-04 | M | P15-AC06 |
| P15-R08 | Effective dating and re-run history: publishing re-allocates every period with `billing_period >= effective_from` that is not closed (Phase 30 hook). Each run is recorded with rule-set version, data version, totals and outcome. | FR-ALC-006 | M | P15-AC07 |
| P15-R09 | Allocation is re-run automatically on `cost.period.normalized.v1` and `cost.period.restated.v1`, idempotently by `(tenant, period, data_version, rule_set_version)`, and emits `cost.period.allocated.v1`. | FR-ALC-005, FR-ING-003 | M | P15-AC07 |
| P15-R10 | ABAC data scopes can restrict by hierarchy node (descendant-of), custom dimension value and normalized tag value. The semantic compiler injects these predicates on `cost_allocated` queries. Cedar decision and SQL predicate are equivalent for all tested scopes. | FR-IAM-006, FR-ANL-004, NFR-SEC-001 | M | P15-AC08 |
| P15-R11 | Showback and chargeback views per hierarchy node: direct cost, shared cost received (by source rule), unallocated cost, per cost metric, per period, drill-down to contributing rules and rows within scope. | FR-ALC-007, UJ-04 | M | P15-AC09 |
| P15-R12 | Untagged and unallocated cost is first-class: a dedicated `(unallocated)` target with reason codes (`no_tag`, `no_rule_match`, `zero_basis`, `excluded_charge_category`). | FR-ALC-005, PRD §11 success metric | M | P15-AC10 |
| P15-R13 | Custom dimensions CRUD with optional allowed-value lists. Assigning a value outside the allowed list fails validation at publish time. | FR-NRM-005, FR-ALC-003 | M | P15-AC03 |
| P15-R14 | Authorization: `allocation:read`, `allocation:edit`, `allocation:publish` permissions. Built-in mapping: FinOps admin and tenant owner publish; finance manager reads; developers and engineering managers see chargeback within scope only. All publish and rule edits are audited (hash-chained log). | FR-IAM-004, FR-IAM-005, FR-AUD-001 | M | P15-AC11 |
| P15-R15 | Rule ASTs are validated against a JSON Schema and a registry of dimensions. No user-supplied SQL. Regex is RE2 with a length cap of 512 characters and a per-rule evaluation time budget. | NFR-SEC-002 | M | P15-AC11 |
| P15-R16 | Performance: allocating one month of 10 M cost rows with 200 rules and 5 shared splits completes within 15 min on the Standard reference hardware (ClickHouse). Preview of one month returns within 60 s. | NFR-PERF-003, NFR-SCL-001 | S | P15-AC12 |
| P15-R17 | Cross-engine parity: `cost_allocated` for the golden dataset is byte-identical (decimal string compare) on PostgreSQL, DuckDB and ClickHouse. | FR-ANL-003, AC-04 | M | P15-AC05 |
| P15-R18 | UI accessibility and i18n for all new pages: WCAG 2.2 AA (axe zero serious/critical), strings externalized, money formatted from string decimals. | NFR-A11Y-001, NFR-I18N-001 | M | P15-AC09 |
