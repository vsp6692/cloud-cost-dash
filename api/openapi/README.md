# CloudLedger OpenAPI contract (DRAFT)

[`cloudledger.v1.yaml`](cloudledger.v1.yaml) is the source of truth for the CloudLedger REST API ([ADR-0011](../../docs/architecture/adr/0011-api-first-rest-openapi-3-1.md)). It uses OpenAPI 3.1.0 and `info.version: 0.0.0-draft`. No implementation exists yet. The contract is refined phase by phase.

- Conventions are defined in [API_GUIDELINES.md](../../docs/contracts/API_GUIDELINES.md), and that document wins if the two disagree. The paths cover every area in the §13 resource catalog.
- Every operation has a unique `operationId`, a tag and `x-phase: "NN"` (the delivery phase). Filter with e.g. `yq '.paths[][] | select(."x-phase" == "13") | .operationId'`.
- Shared components:
  - `Problem` (RFC 9457 + `code`, `request_id`, `errors[]`)
  - `Money` (string decimal `amount` + ISO 4217 `currency`; never a number)
  - `CursorPage` (`data` + `next_cursor`)
  - `Operation` (LRO, returned with `202`)
  - Standard parameters: `limit`, `cursor`, `sort`, `X-CloudLedger-Tenant`, `Idempotency-Key`, `If-Match`
  - Standard 4xx/5xx responses with `Retry-After` and `RateLimit-*` headers
  - `ETag` headers
- SCIM (`/scim/v2/*`, Phase 31) follows RFC 7644 and is referenced in the `SCIM` tag, not re-specified.
- The spec references `../../schemas/semantic/query.v1.json` and `../../schemas/manifest/plugin-manifest.v1.json` via relative `$ref`. Run `redocly bundle` to produce a single file for tools that cannot resolve external refs.

## Editing
The YAML is generated by `scripts/docs/gen_openapi.mjs`, which needs the npm `yaml` package. Edit the generator and re-run it:

```sh
node scripts/docs/gen_openapi.mjs .            # or YAML_MODULE_DIR=<dir with node_modules/yaml> node …
npx --yes @redocly/cli lint api/openapi/cloudledger.v1.yaml
```

Commit the generator and the generated YAML together. Once the API stabilises (Phase 03), the team may decide to make the YAML hand-maintained and retire the generator.

## Planned usage (Phase 03 onward)
| Use | Tooling (planned) |
|---|---|
| Go server types and handler interfaces | `oapi-codegen` (strict server) on the bundled spec, output under `internal/api/gen` |
| TypeScript client for the Next.js BFF/web app | `openapi-typescript` + `openapi-fetch` (or equivalent), output under `apps/web` |
| Lint / structural validation in CI | `redocly lint` (recommended ruleset, with project overrides) |
| Breaking-change check in CI | `oasdiff breaking <base-branch spec> <PR spec> --fail-on ERR`. Breaking changes within `/v1` are blocked (see [COMPATIBILITY.md](../../docs/contracts/COMPATIBILITY.md)) |
| Contract tests | responses from handler tests validated against the spec |
| Docs | rendered reference docs from the bundled spec |

During `0.0.0-draft`, breaking changes are expected. The oasdiff gate becomes blocking once the first phase ships v1 endpoints.

## Known lint warnings (accepted for the draft)
- `no-ambiguous-paths`: `/connectors/templates/{provider}` vs `/connectors/{id}/health|scopes`. Connector IDs are UUIDv7, so the paths can't collide.
- `operation-4xx-response`: `/healthz`, `/readyz` intentionally define no 4xx.
- `no-unused-components`: `AiStreamEvent` (referenced via the `x-sse-event-schema` extension), `Deprecation`/`Sunset` headers (reserved), `scimBearer` (SCIM not specified here).
- `no-required-schema-properties-undefined` in the external JSON Schemas: false positives from `if`/`then` conditional `required` on properties defined in the parent schema.

## Licensing
CloudLedger is **source-available**, not open source. `info.license` currently names the proposed **CloudLedger Source-Available License 1.0** (`LicenseRef-CloudLedger-SAL-1.0`). Per **OQ-22** and [LICENSE_MAP.md](../../docs/legal/LICENSE_MAP.md), Option A (recommended, pending legal review) would license `api/openapi/` under Apache-2.0 so that independent clients and integrations can be written. Option B keeps CL-SAL-1.0.
