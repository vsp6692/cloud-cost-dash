# Schemas (DRAFT)

Machine-readable JSON Schemas (draft 2020-12) for CloudLedger contracts. No application code exists yet. These schemas are drafts and will be refined phase by phase.

| [`events/cloudevent-envelope.v1.json`](events/cloudevent-envelope.v1.json) | CloudEvents 1.0 envelope plus shared `$defs` (`money`, `decimal`, `currency`, `id`, `timestamp`, `billing_period`) | [EVENTS.md](../docs/contracts/EVENTS.md) | 04 |

Event schemas: `tenant.created`, `tenant.deleted`, `connector.verified`, `ingestion.run.completed`, `ingestion.run.failed`, `cost.period.normalized`, `cost.period.restated`, `allocation.published`, `cost.period.allocated`, `budget.threshold.crossed`, `anomaly.detected`, `inventory.snapshot.completed`, `recommendation.created`, `recommendation.state_changed`, `invoice.imported`, `reconciliation.completed`, `period.closed`, `report.run.completed`, `audit.anchor.written` (all `.v1.json`). Each one records its idempotency key in `x-idempotency-key`.

## Conventions
- Money is always `{"amount": "<decimal string>", "currency": "<ISO 4217>"}`. It is never a JSON number.
- Event `data` objects allow additional properties, because consumers ignore unknown fields and evolution is additive. The plugin manifest is strict and rejects unknown fields.
- Some semantic-query limits can't be expressed in JSON Schema, such as filter depth and the maximum time span per grain. They are listed in `x-cloudledger-limits` and enforced by the semantic compiler. Values marked PROPOSED there need confirmation in Phase 13.
- The `$id` domain `schemas.cloudledger.dev` and the event type prefix `dev.cloudledger` are placeholders pending OQ-01.
- The OpenAPI spec (`api/openapi/cloudledger.v1.yaml`) references `semantic/query.v1.json` and `manifest/plugin-manifest.v1.json` by relative `$ref`.

## Regenerating and validating
The files are generated by `scripts/docs/gen_schemas.mjs`. Run `node scripts/docs/gen_schemas.mjs .`, and commit both the script and its output. CI will compile every schema with a JSON Schema 2020-12 validator (Ajv) and validate producer-serialized samples against it (EVENTS.md, "Schema evolution").
