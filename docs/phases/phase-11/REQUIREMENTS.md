# Phase 11 — Requirements

Priority: **M** must, **S** should, **C** could. Every requirement is verified by at least one acceptance criterion in [ACCEPTANCE.md](ACCEPTANCE.md) and test cases in [TEST_PLAN.md](TEST_PLAN.md).

| ID | Requirement | PRD trace | Pri | Verified by |
|---|---|---|---|---|
| P11-R01 | The FOCUS version is pinned explicitly (default 1.2, OQ-02 re-evaluated at phase start). Every normalized row records `focus_version` (via its mapping) and `mapping_version`. | FR-NRM-001, OQ-02 | M | P11-AC01 |
| P11-R02 | `cost_focus` carries every mandatory and every applicable conditional column of the pinned FOCUS version with the spec's data types and value domains. Unsupported conditional columns are NULL and documented per provider. | FR-NRM-001 | M | P11-AC02 |
| P11-R03 | BilledCost, EffectiveCost, ListCost and ContractedCost are populated per the spec. ChargeCategory ∈ {Usage, Purchase, Tax, Credit, Adjustment}; ChargeClass = `Correction` for corrections of prior periods, else NULL. | FR-NRM-003 | M | P11-AC03 |
| P11-R04 | Provider-specific fields are kept as `x_`-prefixed extension columns (documented catalog per provider) and every unmapped source field is preserved in `x_raw`. No source field is silently dropped. | FR-NRM-001, FR-NRM-002 | M | P11-AC04 |
| P11-R05 | Mappings are versioned, immutable once published, and identified by `(key, version, focus_version)`. A mapping change is a new version. | FR-NRM-004 | M | P11-AC05 |
| P11-R06 | Activating a new mapping version can re-normalize selected periods from retained raw objects. Each re-normalized period becomes a new `billing_period_versions` row via staging + atomic swap; previous versions remain queryable for the retention window. | FR-NRM-004, FR-ING-005 | M | P11-AC06 |
| P11-R07 | Tag and label keys are stored raw (FOCUS `Tags`) **and** normalized (`x_tags_normalized`) using a documented deterministic algorithm. Key collisions after normalization are resolved deterministically and reported in the DQ report. | FR-NRM-005, FR-ALC-001 (foundation) | M | P11-AC07 |
| P11-R08 | Tenants can define custom dimensions (key, name, optional allowed values) and assign cloud scopes (account, project, subscription, resource group) to nodes of a published hierarchy version with effective dating. Assignments are queryable as `hierarchy:<node_type>` dimensions. | FR-NRM-005, FR-TEN-003 | M | P11-AC08 |
| P11-R09 | Deduplication is deterministic: `dedup_key = sha256(provider, line_id or natural key, billing_period, charge_period, content_hash[, occurrence_ordinal])`. Re-ingesting the same raw objects yields the identical key set; no two live rows in a period share a key. | FR-NRM-006, FR-ING-003 | M | P11-AC09 |
| P11-R10 | A FOCUS conformance validator checks column presence, types, nullability, value domains and cross-column rules. It runs (a) in CI on golden fixtures, (b) in the provider compatibility suite, (c) on every staged partition before swap. Failures block the swap (fail-closed). | FR-NRM-001, FR-SDK-001 (testkit) | M | P11-AC10 |
| P11-R11 | Golden totals: for each provider golden dataset, Σ normalized BilledCost, EffectiveCost, ListCost and ContractedCost per (billing period, billing account, sub-account, currency, charge category, charge class) equals the source totals exactly (decimal string compare). | NFR-ACC-001, AC-01 | M | P11-AC11 |
| P11-R12 | All monetary and quantity values use fixed-point decimals (`numeric(38,12)`); a lint rule forbids float types in `internal/billing/...`. Source values with more than 12 fractional digits are rejected or rounded only by a documented, mapping-declared rule, and counted in the DQ report. | NFR-ACC-003, ADR-0007 | M | P11-AC12 |
| P11-R13 | Every normalized row links to `ingestion_run_id`, `source_object_id`, `source_row` and `mapping_version` (lineage). | FR-NRM-002 | M | P11-AC04 |
| P11-R14 | Tenant isolation: new control-plane tables have `tenant_id`, composite PK and forced RLS; analytics rows lead with `tenant_id`; mapping and assignment APIs return 404 for other tenants' objects. | FR-TEN-001, NFR-SEC-001 | M | P11-AC13 |
| P11-R15 | Untrusted strings (tag keys/values, resource names, descriptions) are stored as data only. Mapping definitions use a closed expression language (no arbitrary code, no network or file access) with evaluation step and memory limits. | NFR-SEC-002, FR-AI-006 (foundation) | M | P11-AC13 |
| P11-R16 | Mapping publication, activation and re-normalization requests are audited (actor, mapping key/version, periods). | FR-AUD-001 | M | P11-AC14 |
| P11-R17 | Normalization throughput does not regress versus Phase 06 baseline by more than 10% on the PG profile; ClickHouse target (NFR-PERF-003) is measured in Phase 13/34. | NFR-PERF-003 | S | P11-AC15 |
| P11-R18 | `cost.period.normalized.v1` event payload includes `mapping_key`, `mapping_version`, `focus_version`, `data_version`, `period_version`, validated against its JSON Schema. | FR-NRM-004, EVENTS.md | M | P11-AC14 |
