# Phase 27 — Requirements

Priority: M = must, S = should, C = could. Each requirement is verified by the listed acceptance criterion in [ACCEPTANCE.md](ACCEPTANCE.md).

| ID | Requirement | PRD trace | Priority | Verified by |
|---|---|---|---|---|
| P27-R01 | The gateway exposes one provider-neutral interface (chat with tool calling, streaming, token usage). It has adapters for OpenAI-compatible, Anthropic and Ollama-compatible endpoints, selected per tenant. | FR-AI-001 | M | P27-AC01 |
| P27-R02 | AI is **disabled by default** for every tenant. Enabling it requires `ai:configure` and an explicit provider, model and egress policy. Each change is audited (`ai.config.update`). | FR-AI-001, OQ-16 | M | P27-AC02 |
| P27-R03 | Provider credentials are stored only as secret references (`secret://…`), are resolved just in time, and never appear in logs, API responses, prompts or audit details. | FR-AI-001, NFR-SEC-003 | M | P27-AC02 |
| P27-R04 | The model can only invoke tools on the static read-only allow-list. Unknown tools and tools not enabled for the tenant are rejected and audited (`ai.tool.denied`). No tool can mutate state. | FR-AI-002, FR-AI-006, FR-AI-007 | M | P27-AC03 |
| P27-R05 | Every tool executes through the same `authz.Authorizer` and semantic compiler as the REST API, using the requesting user's principal and ABAC scope. The AI module has no database or analytics credentials of its own. | FR-AI-002, NFR-SEC-001 | M | P27-AC04 |
| P27-R06 | NL-to-query: the model's query argument must be JSON that validates against `schemas/semantic/query.v1.json` and the semantic registry. SQL text, unknown fields or unknown metrics or dimensions are rejected. No model-generated SQL is ever executed. | FR-AI-003 | M | P27-AC05 |
| P27-R07 | AI query limits: ≤ 1 000 rows, ≤ 6 dimensions, a time span per grain (day ≤ 93 days, week ≤ 53 weeks, month ≤ 37 months), a compiler cost estimate ≤ the tenant AI budget, and a 15 s execution timeout. Violations return typed errors that the model receives as tool errors. | FR-AI-004 | M | P27-AC05 |
| P27-R08 | Per-user and per-tenant rate limits (requests per minute) and token budgets (daily per user, monthly per tenant) are enforced before the provider call. When exceeded, the API returns `429 query_budget_exceeded` / `rate_limited` with `Retry-After`. | FR-AI-004 | M | P27-AC06 |
| P27-R09 | Untrusted data (tag keys and values, resource names, descriptions, user-supplied text from other users) is placed in delimited, typed data blocks. The system prompt states data is never instructions. Tool results are JSON-encoded and length-capped. | FR-AI-006 | M | P27-AC07 |
| P27-R10 | Output validation: assistant output containing tool-call attempts outside the allow-list, URLs not on the tenant's link allow-list, markdown images or HTML, or secret-like strings is blocked or sanitized before it reaches the client. | FR-AI-006 | M | P27-AC07 |
| P27-R11 | The prompt-injection corpus (≥ 150 cases across direct, indirect via data, tool-argument smuggling, exfiltration-by-URL, role-play and encoding attacks) passes with zero unauthorized tool calls, zero cross-scope data and zero policy-violating outputs. | FR-AI-006, AC-06 | M | P27-AC07 |
| P27-R12 | Data egress policy per tenant: `local_only` (only endpoints flagged local or private and allow-listed), `aggregates_only` (default; tool results sent to the model contain aggregated rows only, with no resource IDs unless the user's question names them), and `allow_rows`. A tenant can opt out of external providers entirely. | FR-AI-008, NFR-PRIV-001 | M | P27-AC08 |
| P27-R13 | Redaction before egress: user emails, IP addresses, account numbers (configurable patterns), and secret-like tokens are masked in prompts and tool results. Masks are reversible only in the UI for the same user. | FR-AI-008 | M | P27-AC08 |
| P27-R14 | All outbound LLM traffic passes `internal/platform/netguard`: per-tenant endpoint allow-list, TLS verification, private and link-local IP ranges blocked unless the operator allows them (Ollama local), and DNS rebinding protection. | FR-AI-001, NFR-SEC-004 | M | P27-AC08 |
| P27-R15 | Conversations are tenant-scoped and owner-scoped. Default retention is 30 days (tenant-configurable 0–365, where 0 means do not persist). Users can delete their own conversations. A purge job hard-deletes expired content. | FR-AI-008, OQ-09 | M | P27-AC09 |
| P27-R16 | Cross-tenant and cross-scope isolation: no tool, conversation, cache or usage path returns data outside the user's tenant or ABAC scope. Questions about unauthorized scopes get a refusal that does not reveal whether the data exists. | NFR-SEC-001, AC-02, UJ-13 | M | P27-AC04 |
| P27-R17 | Groundedness check: an answer that states a monetary value with no corresponding tool result in the turn is flagged `ungrounded` and replaced with a refusal or a re-ask. Full numeric verification is in Phase 28. | FR-AI-005 (precursor) | S | P27-AC10 |
| P27-R18 | Observability: OTel spans per turn and per tool call (with no prompt content). Metrics include `cloudledger_ai_tokens_total{provider,direction}`, `cloudledger_ai_tool_calls_total{tool,decision}` and `cloudledger_ai_provider_latency_seconds`. There is no tenant label at unbounded cardinality. | NFR-OBS-001 | S | P27-AC11 |
| P27-R19 | The gateway works against the deterministic mock adapter in CI. No CI job calls a real provider. Live-provider smoke tests are manual and opt-in. | NFR-MNT-001 | M | P27-AC01 |
