# Phase 09: Requirements

Priority: **M** must, **S** should, **C** could. Each requirement is verified by an acceptance criterion in [ACCEPTANCE.md](ACCEPTANCE.md) and by test cases in [TEST_PLAN.md](TEST_PLAN.md).

| ID | Requirement | PRD trace | Pri | Verified by |
|---|---|---|---|---|
| P09-R01 | Import CSV/TSV (plain, gzip, single-entry zip), JSON (array at a configured JSON pointer), NDJSON, XLSX (one configured sheet) and Parquet through UI upload, API upload and object-store polling. XLS, XLSM, ODS and nested archives are rejected with `unsupported_format`. | FR-IMP-001 | M | P09-AC01 |
| P09-R02 | Uploads use a resumable, chunked upload session (≤ 2 GiB Standard, ≤ 200 MiB Lite; configurable). The server verifies each part's SHA-256 and the whole-file SHA-256 before processing. Re-uploading identical content is a no-op linked to the existing `source_object` (content address). | FR-IMP-001, FR-ING-003 | M | P09-AC01 |
| P09-R03 | Object-store polling (S3/MinIO, GCS, Azure Blob) with include/exclude globs, a settle time (default 5 min), an optional `_SUCCESS` marker or manifest requirement, and period inference from a path pattern or row data. Credentials use keyless federation or secret references. The poller never writes, moves or deletes source objects. | FR-IMP-001, FR-CON-003, FR-CON-004 | M | P09-AC02 |
| P09-R04 | Mapping templates are versioned `mapping_definitions` rows `(key, version, focus_version)`. Published versions are immutable. Every normalized row records `mapping_version`. Built-in templates (`tenant_id = NULL`) are read-only to tenants. | FR-IMP-002, FR-NRM-004 | M | P09-AC03 |
| P09-R05 | The template expression language is closed and side-effect free (arithmetic, decimal, date, string, `map`, `const`, lookups). It has no I/O, reflection or user-defined functions, and each row is bounded by an evaluation step and allocation budget. It is type-checked at save time. | FR-IMP-002, NFR-SEC-002 | M | P09-AC03 |
| P09-R06 | Preview applies a template to the first 1 000 rows (or a supplied sample) and returns mapped rows, per-row validation results and FOCUS mandatory-column coverage. Preview writes nothing to the analytics store, `source_objects` or checkpoints. | FR-IMP-002 | M | P09-AC03 |
| P09-R07 | File-level and row-level validation per GENERIC_IMPORTS.md §4. Every rejection carries a stable reason code. Rows are never silently corrected. If the rejected-row ratio exceeds the threshold (default 1%), the run ends `failed_validation` and the previous live version stays live. | FR-IMP-003, FR-ING-005 | M | P09-AC04 |
| P09-R08 | Each run produces a data-quality report: rows read, accepted, rejected and duplicate; totals per (currency, charge category) with `source_sum = accepted_sum + rejected_sum` exact in decimal; rejections by reason; warnings; periods replaced; and a rejected-row sample (≤ 1 000 rows). | FR-IMP-003 | M | P09-AC04 |
| P09-R09 | Money and quantity parse as decimals into `numeric(38,12)`. Binary floats are never used. XLSX numeric cells use stored text where present; a float-derived value records `x_precision_warning`. Scale above 12 or magnitude overflow rejects the row. | NFR-ACC-003, ADR-0007 | M | P09-AC05 |
| P09-R10 | Golden totals: for each valid corpus file, Σ normalized BilledCost and EffectiveCost per (billing period, billing account, currency, charge category) equals the expected totals exactly. Re-importing the same bytes produces the identical dedup key set and totals. | NFR-ACC-001, FR-NRM-006, FR-ING-003 | M | P09-AC05 |
| P09-R11 | Size and resource safety: per-file size cap; decompressed-size cap (default 20× compressed, hard cap 20 GiB) checked while streaming; zip entry cap; NDJSON line cap 1 MiB; JSON depth cap 64; Parquet column cap 1 000 and string-length cap; per-job memory budget. Exceeding a cap aborts with a typed error and does not leak partial state. | FR-IMP-004 | M | P09-AC06 |
| P09-R12 | XLSX/XML safety: DTDs, external entities and entity expansion disabled; element depth, attribute count and shared-strings caps; macros, external links and embedded OLE rejected or ignored. Archive entry names are never used as file-system paths (zip slip). | FR-IMP-004, NFR-SEC-002 | M | P09-AC06 |
| P09-R13 | Formula-injection neutralization on every CSV/XLSX the platform writes (rejected samples here; exports later): cells starting with `=`, `+`, `-`, `@`, TAB or CR are prefixed with `'` or written as typed text. Valid decimal numbers in declared money columns are exempt. Data is stored verbatim. | FR-IMP-004 | M | P09-AC07 |
| P09-R14 | The declared format must match the magic-byte sniffed format and the declared encoding must decode cleanly. Otherwise the file is rejected. | FR-IMP-004 | M | P09-AC06 |
| P09-R15 | Schema drift: a change in the header/schema fingerprint against the template's last successful import quarantines the run (`quarantined`) and raises an alert, unless the template sets `schema_drift: additive` and only new columns appeared. | FR-ING-006 | M | P09-AC08 |
| P09-R16 | Restatement: re-importing a period (upload or changed object etag) replaces the whole `(tenant, connector, billing_period)` atomically via staging and swap. A deleted source object only raises a warning. | FR-ING-005, FR-NRM-002 | M | P09-AC08 |
| P09-R17 | Lineage: each normalized row links to `ingestion_run_id`, `source_object_id`, `source_row` (1-based line/row number or Parquet row-group:offset) and `mapping_version`. Raw bytes are kept content-addressed under the tenant prefix. | FR-NRM-002 | M | P09-AC05 |
| P09-R18 | Authorization and isolation: `imports:write` to upload or start, `imports:read` to read, `mappings:manage` for templates. Import connectors honour ABAC on `provider = generic`. Other tenants' imports, templates and samples return 404. New tables have forced RLS. Pre-signed URLs are single-object, tenant-prefixed and TTL ≤ 5 min. | FR-TEN-001, FR-IAM-006, NFR-SEC-001 | M | P09-AC09 |
| P09-R19 | Uploads, starts, template publishes and schema quarantines are written to the audit log. Untrusted strings (tags, names) are stored as data only and never logged at INFO. | FR-AUD-001, NFR-OBS-001 | M | P09-AC09 |
| P09-R20 | Throughput: ≥ 1 M rows/min per worker for CSV and Parquet on the Lite reference with the PG adapter, and peak RSS ≤ 512 MiB per import job regardless of file size (non-gating benchmark; gating in Phase 34). | NFR-PERF-003, NFR-SCL-001 | S | P09-AC10 |
