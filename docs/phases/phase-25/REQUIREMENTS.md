# Phase 25 — Requirements

Priority: M = must, S = should, C = could. Each requirement is verified by the acceptance criterion listed in [ACCEPTANCE.md](ACCEPTANCE.md).

| ID | Requirement | PRD trace | Priority | Verified by |
|---|---|---|---|---|
| P25-R01 | The overlap resolver is the only component that sets `net_monthly_savings` and `overlap_group`. Rules emit gross savings, overlap keys and an action class only. | FR-REC-004 | M | P25-AC01 |
| P25-R02 | Candidates are grouped into connected components over shared overlap keys (`resource:`, `resource_shape:`, `resource_schedule:`, `pool:`, `k8s_nodepool:`). Within a group, an `eliminate` candidate wins outright and all others get net 0 with role `alternative`. | FR-REC-004 | M | P25-AC01 |
| P25-R03 | Within each mutually exclusive key (for example `resource_shape`), only the highest-score candidate survives. Ties break by score desc, `rule_id` asc, fingerprint asc. Losers are `alternative` with net 0 and stay visible. | FR-REC-004, UJ-07 | M | P25-AC01 |
| P25-R04 | Surviving candidates are applied sequentially in action-class precedence. Each candidate's net is computed on the projected cost after the previous ones. | FR-REC-004 | M | P25-AC02 |
| P25-R05 | When a resource's usage is covered by a commitment that would become unused after the action, the covered portion of the net is removed. The evidence says so and links to REC-COM-003. | FR-REC-004, FR-FIN-002 | M | P25-AC02 |
| P25-R06 | Invariants hold for every evaluation partition. INV-1: Σ net(r) ≤ S\*(r). INV-2: Σ net(pool) ≤ S\*(pool), and sizing ≤ p10 of the projected eligible spend. INV-3: 0 ≤ net ≤ gross. INV-4: results are the same for any input order. INV-5: tenant totals = Σ net. INV-6: re-running the resolver on its own output changes nothing. INV-7: Σ net of a group never increases when a candidate is added. A violation fails the evaluation job and keeps the prior results live. | FR-REC-004, AC-05 | M | P25-AC01, P25-AC03 |
| P25-R07 | Commitment pools are modeled per provider and type (AWS Compute SP, EC2 Instance SP, standard/convertible RI with size-flexibility normalization; GCP spend-based CUD, resource CUD by region and machine series; Azure reservation by scope and instance-size-flexibility group, Azure savings plan). Each pool has an eligibility predicate and a coverage order. | FR-FIN-002, FR-REC-003 | M | P25-AC04 |
| P25-R08 | REC-COM-001/002 size commitments on the projected post-action hourly eligible series (historical series minus accepted resource nets, distributed hourly). The commitment is set at p10, net of existing commitments. Savings are computed hour by hour (covered on-demand equivalent − commitment cost), which accounts for under-utilization hours. Breakeven months, term and payment option are included in evidence. | FR-REC-003, FR-REC-004, UJ-07 | M | P25-AC04 |
| P25-R09 | REC-COM-003 (underutilized commitment, < 90% for 14 days) and REC-COM-004 (expiring ≤ 60 days) are emitted. REC-COM-004 is labeled `savings_kind = avoidance` and excluded from "savings" totals; it is shown under "cost avoidance". | FR-REC-003 | M | P25-AC05 |
| P25-R10 | REC-REG-001 (cheaper region) is informational (gross = 0, range in evidence) and suppressed when the resource or scope carries a data-residency tag or policy. REC-REG-002 (ARM migration) is emitted only when an ARM equivalent exists in the same region. Unknown OS or AMI architecture support caps confidence at 0.6. | FR-REC-003 | M | P25-AC05 |
| P25-R11 | Software-licensing rules use tenant **license declarations** (Windows Server, SQL Server Standard/Enterprise cores, BYOL eligibility, Azure Hybrid Benefit, AWS License Included vs. BYOL). Without a declaration, REC-LIC-001 emits a `data_gap` note, not a recommendation. REC-LIC-002 defaults to high risk. | FR-REC-003 | M | P25-AC06 |
| P25-R12 | Governance rules REC-GOV-001/002/003 are emitted with `gross = net = 0` and `savings_kind = governance`, with the affected spend amount in evidence. | FR-REC-003 | M | P25-AC06 |
| P25-R13 | Every new rule has deterministic fixtures (identical inputs → identical candidates and evidence hash) and a manifest declaring overlap keys, action class, inputs and default thresholds. | FR-REC-001, AC-05 | M | P25-AC07 |
| P25-R14 | Summary endpoints and UI report totals as Σ net per category, provider and scope, honoring ABAC. Gross values appear only per recommendation and are labeled "before overlap". | FR-REC-002, FR-REC-004, FR-IAM-006 | M | P25-AC08 |
| P25-R15 | The commitment pool simulator (what-if commitment amount, term, payment option) is read-only, deterministic, scoped by `commitments:read`, and returns projected coverage, utilization and savings without creating recommendations. | UJ-07 | S | P25-AC04 |
| P25-R16 | Every resolver run persists an `overlap_resolution_runs` row: partition, `data_version`, input hash, candidate count, invariant results and duration. The resolver output can be reproduced from the stored inputs. | FR-REC-004, FR-AUD-001 | S | P25-AC03 |
| P25-R17 | All arithmetic uses decimals (ADR-0007). Stored savings are `numeric(38,12)` and are rounded only for presentation (half-even). | NFR-ACC-003 | M | P25-AC03 |
| P25-R18 | Cross-tenant and ABAC isolation: pools, overlap groups and summaries never include resources or commitments outside the caller's tenant or scope. Commitments shared across scopes are shown as aggregated pool-level numbers only when the caller holds `commitments:read` on the pool scope. | NFR-SEC-001, AC-02 | M | P25-AC08 |
| P25-R19 | UJ-07 (coverage and utilization → amortized vs. billed → purchase recommendation net of existing commitments and overlaps) passes as Playwright E2E. | UJ-07, AC-09 | M | P25-AC09 |
