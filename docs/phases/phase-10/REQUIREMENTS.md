# Phase 10: Requirements

Priority: **M** must, **S** should, **C** could.

| ID | Requirement | PRD trace | Pri | Verified by |
|---|---|---|---|---|
| P10-R01 | Invoice model: header (provider, invoice number, issuer entity, billing account, invoice date, period, currency, subtotal, tax, total, source, status) and lines (line no, description, category, account ref, service, amount, tax, group key). Unique per (tenant, provider, billing account, invoice number). Money is `numeric(38,12)`. | FR-FIN-004 | M | P10-AC01 |
| P10-R02 | Header integrity: `subtotal + tax = total` and `Σ line amount + Σ line tax = total` are validated exactly. Violations are stored with status `invalid` and excluded from matching. | FR-FIN-004, NFR-ACC-003 | M | P10-AC01 |
| P10-R03 | AWS: invoice summaries via `invoicing:ListInvoiceSummaries` when the capability verifies `pass`. Otherwise upload. Line-level matching uses CUR rows by `bill_invoice_id`. | FR-AWS-005 | S | P10-AC02 |
| P10-R04 | Azure: MCA/MPA invoices via the Billing invoices API (list, get, PDF via short-lived URL) when entitled. MOSP per subscription where verified. EA reports `unknown` with remediation text until verified. | FR-AZR-004 | S | P10-AC02 |
| P10-R05 | GCP: capability `not_applicable` for the API, so the upload path applies. Totals are cross-checked against the billing export by `invoice.month` and `cost_type`. | FR-GCP-004 | S | P10-AC02 |
| P10-R06 | Upload: structured CSV/XLSX/JSON invoice via Phase 09 parsers and an invoice mapping template (`mapping_definitions.kind = invoice_import`), plus optional PDF stored as a source object with user-confirmed header metadata. No OCR of amounts. | FR-FIN-004 | M | P10-AC03 |
| P10-R07 | Importing the same invoice again (same unique key and identical content hash) is a no-op. Different content creates a new invoice revision, keeps the previous one, and re-runs reconciliation. | FR-FIN-004, FR-ING-003 | M | P10-AC03 |
| P10-R08 | Matching uses BilledCost only. Candidate rows come from `InvoiceId` when populated, else from billing account × billing period × currency × issuer mapping. The rule used is recorded per result. | FR-FIN-004, UJ-08 | M | P10-AC04 |
| P10-R09 | Line groups use a versioned per-provider group-key mapping. `variance_g = invoice_amount_g − Σ BilledCost_g` in exact decimal. A header check accounts for unmatched invoice lines and unmatched cost rows. | FR-FIN-004, NFR-ACC-002 | M | P10-AC04 |
| P10-R10 | Every non-zero variance is categorized with the ordered rules `tax, credit, marketplace, support, fx, late_correction, timing, rounding, missing_data, unexplained`, with evidence in `details`. There are zero uncategorized variances. | FR-FIN-004, AC-01 | M | P10-AC05 |
| P10-R11 | Tolerance defaults to 0.01 in invoice currency per line group and is configurable per tenant and provider. A group is within tolerance only if `|v| ≤ tol` and its category is not `unexplained`. `missing_data` and `unexplained` always need acknowledgement. | NFR-ACC-002 | M | P10-AC05 |
| P10-R12 | Reconciliation is deterministic: the result pins `data_version`, `mapping_version` and group-key mapping version, and re-running on the same inputs yields the identical result hash. `cost.period.restated.v1` triggers re-reconciliation; earlier results are marked `superseded` and never deleted. | FR-ING-005, NFR-ACC-001 | M | P10-AC06 |
| P10-R13 | Variance acknowledgement requires `reconciliations:acknowledge`, a reason (≤ 2 000 chars) and `If-Match`. It is audited and is not allowed for the user who imported the invoice when the tenant enables four-eyes (default off). | UJ-08, FR-AUD-001 | M | P10-AC07 |
| P10-R14 | Golden invoice fixtures (AWS, Azure MCA, GCP upload, generic) reproduce the FINANCE_RECONCILIATION §7.1 example and cover each category at least once. Expected results match exactly. | AC-01, NFR-ACC-002 | M | P10-AC05 |
| P10-R15 | Isolation and authorization: forced RLS on new tables; cross-tenant IDs return 404; ABAC by provider and billing account applies to invoices and results; invoice PDFs are served only via single-object pre-signed URLs with TTL ≤ 5 min. | FR-TEN-001, FR-IAM-006, NFR-SEC-001 | M | P10-AC08 |
| P10-R16 | Provider API calls are read-only, rate-limited, classified with SDK error types, and never store invoice PDFs from providers outside the tenant prefix. PDF uploads are size-capped (25 MiB) and magic-byte checked, and are never rendered server-side. | FR-CON-004, FR-IMP-004 | M | P10-AC08 |
| P10-R17 | Events `invoice.imported.v1` and `reconciliation.completed.v1` are emitted via the outbox and validated against their JSON Schemas. | EVENTS.md | M | P10-AC06 |
| P10-R18 | Reconciliation of one invoice with ≤ 5 M candidate rows completes in ≤ 60 s on the Lite reference with the Phase 06 PostgreSQL baseline adapter. Aggregation is pushed to the engine and rows are never exported to the worker. ClickHouse is re-measured after Phase 13 and gated in Phase 34 (non-gating here). | NFR-PERF-001 | S | P10-AC09 |
| P10-R19 | UI: invoice list and detail, variance table with category, evidence and acknowledgement; money shown from string decimals; WCAG 2.2 AA. | UJ-08, NFR-A11Y-001 | S | P10-AC09 |
