# Phase 13 Requirements

Priority: M = must for phase exit, S = should. Each requirement is verified by the listed acceptance criterion in [ACCEPTANCE.md](ACCEPTANCE.md).

| ID | Requirement | PRD trace | Pri | Verified by |
|---|---|---|---|---|
| P13-R01 | Provide an `Adapter` implementation for PostgreSQL, DuckDB and ClickHouse behind one Go interface; the engine is selected by configuration (`analytics.engine`) per deployment, with profile defaults Lite→postgres, Standard/HA→clickhouse (OQ-04). | FR-ANL-001 | M | P13-AC01 |
| P13-R02 | All analytics reads are expressed as semantic queries validated against `schemas/semantic/query.v1.json` and the metric/dimension registries. No business module, handler or UI emits engine SQL (enforced by an import-lint rule: only `internal/analytics/adapter/*` imports DB drivers for analytics). | FR-ANL-002 | M | P13-AC02 |
| P13-R03 | Metric registry includes at least `billed_cost`, `effective_cost`, `list_cost`, `contracted_cost`, `consumed_quantity`, `pricing_quantity`, `savings_vs_list`, `row_count`; each has aggregation, scale 12, and currency behavior (`per_currency` or `converted`). | FR-ANL-002, FR-NRM-003 | M | P13-AC02 |
| P13-R04 | Dimension registry includes FOCUS dimensions (provider, billing_account_id, sub_account_id, service_name, service_category, region_id, resource_id, sku_id, charge_category, charge_class, billing_currency, invoice_id), `tag:<normalized_key>`, `hierarchy:<node_type>`, `dim:<custom_dimension>`. Missing tag values group under `(untagged)`. | FR-ANL-002, FR-NRM-005 | M | P13-AC03 |
| P13-R05 | Identical semantic queries over the identical golden dataset return identical results on all three engines: decimal values compared as canonical strings at scale 12, identical row order for ordered queries, identical NULL/untagged buckets. | FR-ANL-003, AC-04 | M | P13-AC03 |
| P13-R06 | The compiler always injects `tenant_id = $tenant` and the principal's compiled ABAC predicate; there is no compile path without a `SecurityContext`. Queries referencing a dimension the principal cannot see are rejected with `403 forbidden` (dimension known) or filtered, never answered unfiltered. | FR-ANL-004, FR-IAM-006, NFR-SEC-001 | M | P13-AC04 |
| P13-R07 | Engine-level defense in depth: PG RLS on analytics tables; ClickHouse row policy on every tenant table bound to setting `SQL_cloudledger_tenant`; DuckDB per-tenant database file opened only for the context tenant. | FR-TEN-001, NFR-SEC-001 | M | P13-AC04 |
| P13-R08 | Atomic partition swap on every engine (`Stage.Commit`): readers see either the full previous version or the full new version; on `Abort` or crash the previous version stays live; `DataVersion(tenant)` increments exactly once per successful commit. | FR-ING-005 (adapter side), ADR-0010 | M | P13-AC05 |
| P13-R09 | Query limits: max 6 dimensions, max 10 000 rows (1 000 for `ai` profile), max time span per grain (day ≤ 400 days, week ≤ 3 years, month+ ≤ 10 years), timeout (default 30 s), ClickHouse `max_bytes_to_read`, PG `statement_timeout`; violations return typed errors (`422 unsupported_query`, `429 query_budget_exceeded`, `503 analytics_unavailable`). | FR-ANL-002, FR-AI-004 (reserved) | M | P13-AC06 |
| P13-R10 | Result cache keyed by `tenant_id + principal_scope_hash + canonical_query_hash + data_version + engine`; entries are never shared across tenants or scopes and become unreachable on data-version bump. | NFR-SEC-001, DATA_FLOW §2 | M | P13-AC07 |
| P13-R11 | Every query response includes `meta` per API_GUIDELINES §12: `data_version`, `freshness[]`, `completeness`, `query_id`, `currency`, `fx_rate_set_id` (null in this phase). | FR-DSH-003 (enabler) | M | P13-AC08 |
| P13-R12 | All monetary aggregation in decimal; no float in compiler, adapters or result encoding (lint rule). Presentation rounding is half-even; PG uses `cl_round_half_even`, DuckDB `round_even`, ClickHouse `roundBankers`. | NFR-ACC-003, ADR-0007 | M | P13-AC03 |
| P13-R13 | Tag keys/values and filter literals are always bound parameters or engine-escaped literals; injection payloads (`'; DROP`, `{{`, `</script>`, NUL, RTL) are treated as data. | NFR-SEC-002 | M | P13-AC04 |
| P13-R14 | `GET /api/v1/semantic/catalog` returns metrics and dimensions visible to the principal (scope-filtered tag keys and hierarchy node types). | FR-ANL-002 | M | P13-AC08 |
| P13-R15 | Analytics migrations per engine are versioned, forward-only and idempotent; `cloudledger migrate analytics` reports applied versions. | FR-OPS-004 (enabler) | M | P13-AC01 |
| P13-R16 | Observability: spans per compile/execute with engine, cache hit, rows, bytes; metrics `cloudledger_analytics_query_duration_seconds{engine,outcome}`, `cloudledger_analytics_cache_hits_total`; no tenant label (NFR-OBS-001); billing values never logged at INFO. | NFR-OBS-001 | M | P13-AC09 |
| P13-R17 | Baseline performance recorded for each engine on the Lite fixture (5 M rows): dashboard-style query p95 recorded, target ≤ 5 s on PG (NFR-PERF-001 Lite). Not gating for ClickHouse reference scale (Phase 34). | NFR-PERF-001 | S | P13-AC10 |
| P13-R18 | Engine unavailability degrades gracefully: `503 analytics_unavailable` with `Retry-After`; no fallback to another engine (avoids silent semantic differences). | NFR-AVL-001 | M | P13-AC06 |
