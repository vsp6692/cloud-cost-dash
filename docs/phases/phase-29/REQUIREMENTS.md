# Phase 29 — Requirements

Priority: M = must, S = should, C = could. Every requirement is verified by at least one acceptance criterion in [ACCEPTANCE.md](ACCEPTANCE.md).

| ID | Requirement | PRD trace | Priority | Verified by |
|---|---|---|---|---|
| P29-R01 | A reconciliation run matches invoice line groups to normalized `BilledCost` by (invoice_id where present, billing period, billing account, currency, category), pinned to a `data_version`, and stores a result with invoice total, computed total and tolerance. | FR-FIN-004, UJ-08 | M | P29-AC01 |
| P29-R02 | Every non-zero difference is decomposed into categorized variances. The sum of variances equals `invoice_total − computed_total` exactly. Residual that no categorizer explains is `unexplained`, never dropped. | FR-FIN-004, NFR-ACC-002, AC-01 | M | P29-AC01, P29-AC02 |
| P29-R03 | Result status is `matched` (difference 0), `within_tolerance` (|diff| ≤ tolerance, default 0.01 per line group in invoice currency), or `variance`. Tolerance is configurable per tenant and provider and recorded on the result. | NFR-ACC-002 | M | P29-AC02 |
| P29-R04 | Users with `reconciliations:acknowledge` can acknowledge a variance with a mandatory reason (≥ 10 chars) and category confirmation or re-categorization. Acknowledgment is audited (`variance.acknowledge`) and is immutable; correcting it requires a superseding acknowledgment. | FR-FIN-004, FR-AUD-001, UJ-08 | M | P29-AC03 |
| P29-R05 | Optional separation of duties: when `finance.reconciliation.require_sod=true`, the acknowledger must differ from the run initiator and from the uploader of the invoice; violations return 403 and are audited. | FR-FIN-004, NFR-SEC-002 | S | P29-AC03 |
| P29-R06 | On `cost.period.restated.v1` or `invoice.imported.v1` for an affected period, reconciliation re-runs automatically. Prior results are retained; acknowledgments on changed variances are marked `stale` and require re-acknowledgment. | FR-ING-005, UJ-08 | M | P29-AC04 |
| P29-R07 | Showback and chargeback exports per hierarchy node (and optional custom dimension) from `cost_allocated`, including an explicit `unallocated` row, so Σ export = source total for the period. | FR-ALC-007, FR-ALC-005, UJ-04 | M | P29-AC05 |
| P29-R08 | GL mappings are versioned, effective-dated, and map (hierarchy node, custom dimension, charge category, provider) → (GL account, cost center, legal entity, tax code) with explicit precedence and a mandatory default (suspense) account. Publishing requires a preview diff. | FR-FIN-006 | M | P29-AC06 |
| P29-R09 | Journal export produces balanced entries: per (entity, currency, period) Σ debits = Σ credits exactly. Rounding to the ledger's currency minor unit uses half-even; residuals are posted to a configured rounding account deterministically. | FR-FIN-006, NFR-ACC-003 | M | P29-AC06, P29-AC07 |
| P29-R10 | Export formats CSV, XLSX, JSON/NDJSON, Parquet and PDF (summary only), with money as fixed-scale decimal strings (CSV/JSON), decimal(38,12) (Parquet) and text-formatted numeric cells with explicit number format (XLSX). | FR-FIN-006 | M | P29-AC08 |
| P29-R11 | CSV and XLSX writers neutralize formula injection: any cell whose first character is `=`, `+`, `-`, `@`, TAB (0x09) or CR (0x0D) is prefixed with `'`; numeric money columns are typed, not strings, so negative amounts are unaffected. | FR-IMP-004 | M | P29-AC09 |
| P29-R12 | Export-to-ledger validation runs on every export before it is marked `succeeded`: row-count parity, Σ amount per (currency, period, cost metric) == the source semantic query result exactly, journal balance, and `data_version` unchanged. Failure → `failed_validation`, artifact quarantined, no download URL issued. | FR-FIN-006, AC-01 | M | P29-AC07 |
| P29-R13 | Each export produces a manifest (canonical JSON) with source query, `data_version`, rule-set version, GL mapping version, FX rate set, per-file SHA-256, row counts and control totals. The manifest hash is recorded and audited. | FR-FIN-006, FR-AUD-001 | M | P29-AC10 |
| P29-R14 | Exports stream to object storage (`exports/{tenant_id}/{export_id}/…`) with bounded memory (≤ 256 MiB per job) and support ≥ 100 M rows; downloads use per-object pre-signed URLs with TTL ≤ 15 min. | NFR-SCL-001, FR-FIN-006 | M | P29-AC11 |
| P29-R15 | Exports apply the requester's ABAC scope; a requester cannot export data they cannot query. Cross-tenant export IDs return 404. Export of a scope narrower than the tenant is labeled "partial scope" in the manifest. | NFR-SEC-001, FR-IAM-006, AC-02 | M | P29-AC12 |
| P29-R16 | Export, reconciliation and GL mapping operations are long-running operations (202 + Operation), require `Idempotency-Key`, and are rate-limited in the `export` bucket. | API_GUIDELINES §6, §8, §9 | M | P29-AC11 |
| P29-R17 | UJ-08 steps (import → automatic match → variance report → acknowledge) and the chargeback step of UJ-04 pass as Playwright E2E against fixture data. | UJ-08, UJ-04, AC-09 | M | P29-AC13 |
